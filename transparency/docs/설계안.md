# 투명성 「루미튜브로 발표 준비하기」 설계안 (Prompt 5 형식)

GAME ID `transparency` · 일반 미니게임형(Prompt 3A) · 초등 5~6학년 · 12~15분 · 혼자 플레이

## 1. 한 문장 게임 요약
내일 발표를 위해 루미튜브 숏츠에서 사실 카드 5장을 모으는데, 1일차엔 AI 표시·추천 이유가 없어 발표에서 속은 걸 겪고, 2일차엔 표시와 이유가 켜져 내가 고를 수 있게 되며, 3일차엔 내가 AI 도움으로 만든 영상에 「AI 도움받음」 표시를 붙일지 선택한다.

## 2. 화면/장면 목록과 전환도
```
START(캐릭터·닉네임) → INTRO(ai_lab, 하늘쌤·루미) → RULE(사용법)
 → FEED1(ai_lab + 폰 피드, 표시 없음, 카드 5장) → PRESENT1(classroom, 카드별 반응·AI 카드 공개·결과)
 → THINK1(생각 카드 1) → DAY2(ai_lab, 하늘쌤이 설정 켬) → FEED2(표시·왜 추천? 피드)
 → PRESENT2(끄덕임, 1일차 비교) → THINK2 → MAKE(문장 3개 고르기) → LABEL(표시 붙일까?)
 → OUTCOME(classroom, 붙임/안 붙임 분기 → 공통 되돌아보기) → COMPLETE(발견한 것·한 문장·비교·다시 하기)
```
동작 하나: 폰 피드에서 영상을 탭해 카드로 가져오기(「다음 영상」 버튼·위로 밀기·↓ 키).

## 3. 상태 모델
```
S = { stage, player('jiho'|'haneul'), nick,
      day, cards[{id,known}], pool[], tapped{topic:n}, seenCount, seenTopics, current, timerLeft, pendingConfirm,
      day1{cards,fooled,aiKnown,seen,topics}, day2{…}, thinks[2], aiUsed(0~3), label('on'|'off'),
      presentIndex, presentStep(0 발표·1 반응·2 공개·3 요약), makeIndex }
```
영상 데이터 30개 = {id, title, topic, fact, glyph, isAI, tellType, tell, react, views}. 추천 가중치 = 1 + 1.5×tapped[topic] + 2.5×isAI.

## 5. 새로 필요한 게임 전용 asset
- 숏츠 썸네일 30장(240×180) + 폰 틀·사실 카드·슬라이드 틀·배지 2·왜 추천? 꼬리표·시청 지도 판 = 코덱스 납품 37장(`assets/`, manifest.json 등록). 파일이 없으면 캔버스 임시 픽셀 글리프(19종 + 티 4종)·CSS 틀로 폴백.

## 6. .ee-* 재사용 목록

## 7. 게임 전용 컴포넌트
.tp-phone.has-frame/.tp-screen(코덱스 폰 틀 안 피드) · .tp-bubbles/.tp-bubble(장면 위 반응 말풍선) · .tp-factcard(사실 카드 틀) · .tp-viewmap(시청 지도) · .tp-thumbwrap/.tp-thumb-badge(썸네일+AI 제작 배지) · .tp-slots(카드 5칸) · .tp-timer · .tp-confirm · .tp-slide(발표 카드, flipped) · .tp-table(비교표) · .tp-found(발견한 것) · .tp-charpick · .tp-field(닉네임)

## 8. CSS namespace
모든 전용 규칙은 `.game-transparency …` 아래. --ee-* 토큰·.ee-* 핵심 컴포넌트 재정의 없음(배치·크기·간격만).

## 9. 저장 키
`ethicity.transparency.player` · `.progress` · `.sfx` · `.result` (README 참조). 개인정보 없음, try/catch.

## 10. 모바일 조작
430px에서 장면은 16:9 축소(약 398×224), 폰은 전폭 332px 이하로 아래 배치. 폰 버튼 2개(가져오기/다음) 48px↑, 위로 밀기 스와이프 지원, 확인창 버튼 전폭. 발표 내용은 패널 카드에 글자로 중복 표시. 가로 스크롤 없음.

## 11. 키보드/접근성
실제 `<button>`, data-autofocus로 단계마다 주 버튼에 초점, Tab/Enter/Space, ↓·→로 다음 영상, aria-pressed(선택·효과음·왜 추천?), role=status 안내, 캔버스 aria-label 장면 설명, 썸네일 canvas role=img, focus-visible 유지(common.css), 색+아이콘+문구로 상태 구분, prefers-reduced-motion에서 페이드·뒤집기·타이머 전환 제거 및 효과 정지 프레임.

## 12. 통합 이벤트
ready(로드 후) · progress(단계 전환마다 current/total 13) · complete(완료 화면에서 result {completed, day1Fooled, day2Fooled, labeled, thinks}). postMessage만 사용.

## 13. 탐험형 아님
1280×720 논리 화면은 장면(ai_lab·classroom)에만 사용, 이동 없음. 좌표: 플레이어 (290,455) · 하늘쌤 (420,455)/(330,335) · 발표자 (640,300) · 친구 (100,400)(215,400)(1065,400)(1180,400) · 칠판 슬라이드 (468,20,344,118).

## 14. 공통 SFX/effect 계획
tap=버튼, paper=카드 가져오기, door=장면 전환, miss=AI 카드 공개(부드럽게), retry=1일차 결과, collect=생각 카드 선택, win=2일차 결과·완료. effect retry/correct/clue.

## 15. 실패 가능성과 대응
- 1일차에 전부 진짜만 고를 수 있음 → 분기 문구("5장 모두 진짜였어요! 그런데 표시가 없어서…")로 메시지 유지.
- 2일차 AI 표시 영상을 그대로 가져올 수 있음 → 확인창 뒤 `known` 카드로 기록, 발표에서 "표시가 있었어요" 자진 공개 → 속은 카드 0 유지.
- 타이머가 끝나도 카드가 부족함 → 벌 없이 계속 고를 수 있음(안내 문구만).
- 캔버스 글꼴 미로드 → document.fonts.load 후 그리기, 실패 시 fallback.
- 썸네일 PNG 미납품 → 임시 글리프 자동 사용, 404 없음(manifest.json 동봉).
- localStorage 차단 → try/catch, 게임 계속.
