# 안전성 「닥터루미 창구」 설계안 (Prompt 5 형식)

윤리시티 · AI 윤리 탐험대 — gameId `safety` · 담당 김햇살(초) · 공통 팩 `ethicity-elementary-common-v1` 1.0.0 기준 · 규칙은 `설계_v4_인터랜드형.md` ① 안전성 절(v4.1) 그대로.

## 1. 한 문장 게임 요약
보건실 창구에서 AI 닥터루미(robot)가 먼저 답하면, 책상 위 증거 카드와 비교해 **맞으면 아이를 오른쪽(침대) / 틀렸으면 왼쪽(보건쌤)으로 미는** 동작 하나로 사흘(1일차 기본 → 2일차 닥터루미가 못 보는 카드 → 3일차 안전장치)을 보내며 "AI가 자신 있게 말해도 중요한 건 사람이 다시 확인한다"를 몸으로 익힌다.

## 2. 화면/장면 목록과 전환도
```
START(캐릭터 2종·닉네임) → WALK(중앙마당→보건실 문, 건너뛰기) → INTRO(보건쌤 4마디)
→ DAY1 150초 → THINK1 60초 → DAY2 180초(못 보는 카드·보스) → THINK2 60초
→ DAY3 180초(안전장치 스위치 장면 → 잠김/해제) → REPORT(3일 보고서) → COMPLETE(발견한 것·한 문장·다시 하기)
```
- 하루 = 「N일차」 자막 카드(무대 안) → 보건쌤 소개 말풍선(데크) → 시작 버튼 → 창구 플레이 → 하루 끝 안내 → 다음 단계.
- 모든 화면이 한 페이지 안: HUD(상단) / 무대 1280×720 캔버스(비율 유지 축소) / 창구 데크(말풍선·카드·버튼 2개) / 전체 화면 패널(시작·생각 카드·보고서·완료).

## 3. 상태(state) 모델
- `player` {character: 'jiho'|'haneul', nick} — 저장 `ethicity.safety.player`
- `game` {stage, cond: 'new'|'old'(최신판 5% / 옛 버전 25%, 시드로 결정, 완료 화면에서 공개), records{day1..3: cared·acc·caught·busy·timeouts·maxQueue·avgWait}, answers{think1, think2}, seenWrong, progress}
- 하루 런타임 `R` {cfg, cases[], idx, t, spawnT, queue[], window(창구 아이), holdUntil, extra(줄 +1), cared, acc, caught, maxQueue, tut{pause, step}}
- 아이 `kid` {c(케이스: topic·cards[2~3]·key·hidden·unseen·danger·line·ai{wrong, conf, line, unseenKey, human}), actor, state: queue→toWindow→window→leaving, flipped[], tapped[], patience}
- 무대 `scene` {bg, actors[], props[], fx[]} — 발 기준 y 로 그리기 순서 정렬.

## 6. .ee-* 공용 UI 컴포넌트 재사용 목록

## 7. 게임 전용 컴포넌트

## 8. CSS namespace 계획
모든 게임 규칙은 `.game-safety …` 아래. `--ee-*`·`.ee-*` 는 재정의하지 않고 배치/크기만 자식 선택자로 보강(예 `.game-safety .sf-actions .ee-button{min-height:64px}`). 색은 토큰만 사용(캔버스 임시 카드도 팔레트 + 살색 1색).

## 9. 저장 키 계획
`ethicity.safety.player` {character, nick} · `ethicity.safety.sound` 0/1 · `ethicity.safety.result` {completed, ending, cond, days[3]{acc,caught,maxQueue,cared}, at}. 다른 키 없음. 닉네임은 기기 로컬에만.

## 10. 모바일 조작 계획
- 밀기 = 무대 위 스와이프(40px↑) / 데크의 큰 버튼 2개(최소 64px) / ←→ 키 — 셋 다 같은 `act()`.
- 카드 탭 = 실제 `<button>`(48px↑), 숫자 키 1~3 겸용.
- 760px·430px: 데크가 한 열로 쌓임, 카드 그림 76~84px, HUD 2줄, 가로 스크롤 없음. 무대 `touch-action:none`(스와이프), 데크는 기본 스크롤.

## 11. 키보드/접근성 계획
- 실제 button, Tab 초점 유지(focus-visible 공통 outline), 화면 전환 시 첫 버튼으로 초점 이동.
- `aria-pressed`(캐릭터·생각 카드·증거 카드 탭 여부), 잠긴 침대 버튼은 `aria-disabled` + 자물쇠 아이콘 + "잠김" 글자(색만으로 구분 안 함), 카드 표식은 아이콘 + "봄/못 봄" 글자.
- `aria-live`(데크 polite, 보조 안내 assertive)로 닥터루미 답·결과 읽어 줌.
- prefers-reduced-motion: 걷기 → 즉시 이동, 효과 정지 프레임, 카드 뒤집기/맥동 애니메이션 꺼짐(공통 CSS + 게임 CSS).

## 12. 부모 페이지 통합 이벤트
- 로딩 완료 `{type:'ethicity:ready', gameId:'safety'}`
- 진행 `{type:'ethicity:progress', gameId:'safety', current, total:7}` — 소개 1, 1일차 2, 생각1 3, 2일차 4, 생각2 5, 3일차 6, 보고서 7
- 완료 `{type:'ethicity:complete', gameId:'safety', result:{completed:true}}` — 닉네임·개인정보 없음. 부모 DOM 접근 없음.

## 14. 공통 SFX/effect 사용 계획
맞음 correct+collect · 틀린 AI 잡음 correct+collect(+보건쌤 쪽 clue) · 더 아파짐 retry+retry(+miss) · 불필요 확인 miss · 탭·버튼 tap · 입장·하루 시작 door · 하루 끝·보고서 paper · 잠금 해제 unlock+collect · 안전장치 켜기 key→unlock · 완료 win. 사이렌·흔들림·GAME OVER 없음. BGM 없음.

## 15. 실패 가능성이 높은 부분과 대응
- 줄이 너무 길어져 압도감 → 줄 상한 8명(넘치면 복도 대기), 시간 안 밀면 닥터루미 답대로(벌점 없음).
- 아이가 "AI 맞음/틀림"을 못 읽음 → 1일차 첫 3명은 시간 정지 교습(답 보기→카드 비교→밀기, 틀린 예, 숨은 카드), 카드 위험 값은 글자+색.
- 3일차 잠김을 못 풀고 멈춤 → 핵심 카드에 맥동+“탭!” 글자, 잠긴 버튼 누르면 안내, 시간 종료 시 닥터루미 답대로 자동 처리.
- 캔버스 임시 카드 그림체 이탈 → 납품 PNG 우선 로더, 폴백은 팔레트 색만.
- 타이머 배열 정리 중 콜백 예외 → 스냅샷 실행(수정 완료), 프레임 루프를 먼저 예약.
