# 검증 및 공개 배포 기록 · 2026-11-14

## 교사 동시 진행 수정

- 교사의 현재 이야기를 모든 학생에게 즉시 적용. 안내 또는 이전 이야기 진행 중인 학생도 이동하며, 먼저 끝낸 학생은 대기.
- 여섯 번째 이야기 뒤 학습 정리도 교사가 함께 열도록 제어. 미완료 선택·이야기 완료 기록을 임의로 생성하지 않음.
- 최초 입장 화면에 닉네임, A/B 탐험가, 수업 참여/미리보기 선택 통합. 수업 중 미리보기 전환 제거.
- 미완료 선택도 개인정보를 제거한 개인 체크포인트에 보관하고, 재참여 시 교사의 현재 이야기로 복원.
- 에뮬레이터 43개 검사 통과. 실제 브리지 검사: 서로 다른 선택 유지, 미완료 학생 강제 이동, 빠른 학생 대기, 일시정지/재개, 오래된 제어 무시, 재참여, 학습 정리 열기, 입장 전 미리보기 독립 실행 통과.
- 브라우저: 안내 중 첫 이야기 이동, 선택 피드백 도중 다음 이야기 이동, 새로고침 후 교사 현재 이야기 입장, 6개 이야기와 결과까지 강제 이동, 독립 미리보기 유지 확인. 학생 오류 로그 없음.
- 입장 화면은 1280×720, 760×1024, 430×932에서 가로·세로 스크롤 없이 닉네임·탐험가·두 진행 방식이 모두 보임.
- 수정된 규칙을 실제 Firebase에 배포하고 12개 실제 서버 검사 통과. 교사가 학습 정리를 열기 전 결과 제출 차단, 연 뒤 미완료 선택을 꾸며내지 않고 개인 결과 완료 가능함을 확인. 임시 검증 방은 종료함.
- 공개 사이트 저장 버전 8, 소스 커밋 `848d8995cf6f763e90920d35e02c37184b78a4b7` 배포 성공. 기존 게임 허브의 실행 URL을 그대로 사용.
- 공개 브라우저에서도 닉네임·B 탐험가로 참여 → 안내 중 교사의 첫 이야기 열기 → 아무 선택도 완료하지 않은 상태에서 다음 이야기 열기 → 즉시 이야기 2 이동 확인. 학생 오류 로그 없음. 검증 수업은 종료함.

## 자동 검사

- 기존 8,192개 상태 조합: 결과 분기, 안전 확인, 기준 추가와 재시험 분리, 작동 권한, 시나리오 ID, 기록 불변성 통과.
- 실제 Auth/Firestore Emulator Suite: 학생 2명의 독립 선택·분기·체크포인트, 공개 전 집계 차단, 교사 전용 제어, 학생 간 기록 접근 차단, 재전송 중복 방지 등 닉네임 검사 포함 39개 검사 통과.
- 실제 `game-bridge.js` 실행 검사: 이야기 잠금, 일시정지/재개, 잘못된 출처 메시지 차단, 미리보기 후 잠금 무시와 제출 중지 통과.
- `scenario.js`, `story.js`, `report.js`, `food.js`의 SHA-256이 v4와 같음.

## 브라우저에서 확인

- 교사 수업 생성 → 코드로 학생 참여 → 학생 익명 번호가 교사 진행표에 표시.
- 교사 시작 전 첫 이야기 진입 대기 → 첫 이야기 열기 → 학생이 이어서 시작.
- 학생의 첫 선택 → 첫 이야기 완료 인원과 선택 분포에 반영 → 다음 이야기 대기.
- 집계 공개 버튼 → 학생의 우리 반 선택 버튼 생성 → 공개된 숫자 표시.
- 학생 새로고침/재참여 → 같은 익명 번호 → 이야기 1 완료 기록 복원 → 이야기 2부터 진행.
- 교사 잠시 멈추기 → 학생 입력을 가리는 대기창 표시, 기존 선택 유지.
- **Auth/Firestore 서버 프로세스를 중단** → 대기 중 미리보기 전환 → 기존 게임 화면·기준 카드 1장 유지, 선택 버튼 활성화. 이후 서버 재시작.
- 430×932 모바일 선택 화면과 760×1024 태블릿 선택 화면 확인. 760px에서 부모 문서와 게임 iframe 모두 가로/세로 overflow 없음.
- 최초 연결/정상 플레이에서 애플리케이션 오류 로그 없음. 서버 중단 시험 중 Firebase 재연결 오류는 예상한 장애 신호.

## 운영 범위

- 실제 Firebase 프로젝트는 `ethicity-reliability-20261114`, Firestore Standard 서울 리전, 익명 인증, 검증한 기본 거부 보안 규칙을 사용.
- 약 23시간 뒤 방 참여·제출을 막으며 자동 삭제는 제공하지 않음. 운영자가 Firebase Console에서 방과 하위 기록을 함께 정리.
- 교실 Wi-Fi·다수 실제 태블릿 부하·장기 사용량은 아직 검증하지 않음.
- 미리보기 전환 후 진행은 현재 탭 메모리에 유지되며 새로고침/탭 종료 복원은 제공하지 않음.
- PNG 생성 코드는 변경하지 않았고, 기존 결과 모델과 리포트 원본 동일성을 확인함.

## 닉네임 추가 확인

- 학생 참여 시 한글·영문·숫자 1~12자 별명 입력. 실명 사용을 피하도록 안내.
- 동일 닉네임을 가진 학생 2명의 UID와 선택은 분리됨. 본인 재참여 시 닉네임만 변경 가능.
- 공백·과도한 길이·마크업·제어문자·다른 학생 닉네임 변경 차단 검사 통과.
- 브라우저에서 초록별로 입장 후 학생 상단·교사 진행표에 표시되는 것을 확인.

## 실제 Firebase 및 공개 주소 검사

- `tests/production.mjs --run-production-smoke`: 실제 서버에서 교사 1명·학생 2명으로 11개 검사 통과. 같은 닉네임의 UID 분리, 다른 학생 기록 접근 차단, 교사 제어권, 잠긴 이야기 제출 차단, 실시간 열기, 서로 다른 선택 저장, 개인 체크포인트 보호, 명시적 집계 공개, 교사의 학생 답변 덮어쓰기 차단, 미리보기 후 제출 차단, 종료 후 제출 차단.
- 공개 주소 `/data/data_v5/`에서 교사 수업 생성 → 닉네임 `검증별` 학생 참여 → 교사 명단에 표시 확인.
- 교사의 첫 이야기 열기와 잠시 멈추기 → 학생 대기창 표시 확인.
- 학생 미리보기 전환 → 같은 화면·탐험가 유지 → 교사 수업 종료 후에도 다음 대사 진행 확인. 교사 명단에는 미리보기·집계 제외 표시.
- 공개 학생 화면의 오류 로그 없음. 배포 직후 첫 탐색은 일시적인 HTTP 오류가 있었으나 후속 HTTP 200과 새 브라우저 탐색으로 정상 응답 확인.
- SDK 검증 방과 브라우저 검증 방은 종료 처리. 실제 학생 자료는 사용하지 않음.
- 공개 사이트 저장 버전 7, 소스 커밋 `a9ebb847c4ad68496722206bbdd877868964ea36` 배포 성공.
- 허브의 7번 데이터 관리 게임 URL만 `/data/data_v5/`로 저장. 제목·설명·썸네일·소개 슬라이드는 유지.
