# 윤리시티 매직메이커AI 공방 · harm v3

초등학교 3~4학년이 교사와 함께 하는 침해금지 게임이다. 10월 31일 승인 시나리오에 **11월 1일 승인한 문맥 수정안**을 반영했다. 사진 사용의 허락과 실제 피해 여부를 분명히 하고, 분기별 대사·선택지·결과와 엔딩별 실천 약속을 다듬었다. 최신 요청에 따라 제작 경로는 `harm/harm_v3/`이며, 기존 `harm/`와 `harm/v2/`는 유지한다.

- 게임: https://ethicity-privacy-20261011.web.app/harm/harm_v3/
- 교사: https://ethicity-privacy-20261011.web.app/harm/harm_v3/?mode=teacher
- 승인 문서: https://docs.google.com/document/d/1t46gZZR_H5d-rjvYcCW4vvVNHVELfakbWEP0agIqxrQ

## 사용 방법

1. 교사가 웹 주소에서 ‘교사 컨트롤타워’를 누르고 새 수업을 만든다.
2. 화면의 학생 입장 링크를 공유한다. 모든 학생이 입장한 뒤 수업을 시작한다.
3. 이야기와 위험 신호를 충분히 읽고 투표를 연다. 투표만 20·40·60·90초로 정하며, 일시정지·15초 추가·직접 마감이 가능하다.
4. 동률이면 가장 많은 표를 받은 선택 중 교사가 결정한다. 0표이면 다시 투표한다.
5. 8라운드 뒤 공동 엔딩과 학급의 답을 함께 확인한다. 학생 기기에 완료 기록이 저장된다.

`index.html` 하나에 그림·글꼴·음악·코드가 들어 있다. 내려받은 파일에서는 **수업 미리보기**를 인터넷 없이 할 수 있다. 여러 기기를 연결하는 실시간 수업은 위 웹 주소를 사용한다. GitHub에서 파일이 커서 미리보기를 표시하지 못한다는 안내가 나올 수 있으며, 실행 오류는 아니다.

## 이번 버전의 이야기와 저장

- 8라운드: 얼굴 규칙 → 목소리 규칙 → 다온 사진 → 새봄 할머니 전화 → 몰래 사람 찾기 제안 → 사진관 협업 → 실제 조치·지원 → 다음 축제 약속.
- 1·2라운드 선택을 3·4라운드 상황에 반영한다. 7·8라운드에는 실제 피해 여부, 이미 한 조치, 행사 일시 중단 여부를 함께 반영한다.
- 축제 인기와 마을의 믿음은 각각 0~16칸이다. 개인 표 수가 아닌 학급 확정 선택에 한 번만 더한다. 새로고침·재접속은 점수를 더하지 않는다.
- 사진·목소리·몰래 사람 찾기·사진관 대응을 따로 표시한다. ‘약속한 행동 확인’은 우리 반이 하기로 한 일을 실제로 확인했다는 뜻이며, 피해가 모두 원상 복구됐다는 뜻은 아니다.
- A: 믿음 12 이상 + 네 항목 해결 + 7라운드 지원 실행 + 8라운드 종합 약속.
- B: A가 아니고 믿음 6 이상 + 사진·목소리·몰래 찾기의 위험한 기능을 모두 멈추고 점검함.
- C: 나머지. 이미 막은 위험을 다시 생긴 것으로 설명하지 않는다.
- 상황 설명은 `~한다`, 결과·안내는 `~해요`, 직접 대사는 관계에 맞는 친근한 말투이다. 한 줄 카드는 40자 이내 `~겠습니다`로 끝나는 엔딩별 실천 약속이다.
- 회사 이름과 화자는 `A기업`, 사진관 인물은 `반짝사진관 사장님`으로 통일했다. 승인 원문은 `source/scenario-approved-2026-11-01.txt`에 있다.
- 모든 선택에 ①~⑤ 학습 꼬리표를 데이터로 두며, 학생 선택지에는 표시하지 않는다.

캐릭터 저장은 `ethicity.player`의 `{character, nickname}`을 그대로 쓴다. 결과는 모든 엔딩에서 `ethicity.result.harm`에 `{game:"harm", completed:true, ending:"A|B|C", card:"..."}`로 저장한다. 교사 기기에는 학생 완료 배지를 저장하지 않는다. 저장 차단 환경에서도 학습을 끝까지 진행한다.

실시간 수업은 기존 방과 분리한 `roomsHarmV3`, 시나리오 버전 `harm-2026-11-01-v3.1`를 쓴다. `database.harm-v3.rules.json`은 이 가지에 대한 **추가 조각**이다. 전체 서버 규칙을 이 파일만으로 덮어쓰지 않는다. 기존 규칙을 읽고 이 가지를 합쳐 적용하며, 서버에서도 엔딩·카드·학생 자신의 투표·투표 시간을 검증한다.

이전 v3로 이미 시작한 수업의 저장은 `source/legacy-v3-cards.json`으로 유지한다. 새 시나리오는 새 수업으로 시작하며, 서버는 방의 버전에 맞는 카드만 허용한다.

## 그림·소리

공통 팩의 캐릭터·배경·소품·아이콘·효과·효과음·글꼴·CSS·그리기 코드는 원본을 유지한다. 장면 8개는 원본의 합성이며, 분기별 사실은 실제 글로 표시한다. 다온은 공통 팩의 여자 캐릭터이다. 도담·모아 역할은 온유·새봄으로 교체했다.

승인한 새 인물 3명은 `assets/manifest.extension.json`에 게임 전용 확장으로 등록했다. `grandmother`, `photographer`, `company_staff`가 있으며, 원본 시안과 4개 표정·정지 모습을 함께 보관한다. 새 인물은 걷기 애니메이션이 없으므로 `drawCharacter`에서는 `down`, frame `0`만 쓴다. 공통 팩 자체는 변경하지 않는다. 생성 단계의 프롬프트는 `source/character-design-provenance.json`에 기록했다.

사용자가 2026-10-31에 제공한 **Pixel Adventure (1).mp3**를 `assets/sounds/pixel-adventure.mp3`로 그대로 추가했다. 첫 게임 버튼 조작 후 기본 18%로 반복 재생한다. 화면·소리 메뉴에서 켜기/끄기·볼륨을 조절하고 설정을 기기에 저장한다. 탭을 숨기면 일시정지하고, 처음 화면으로 나가면 멈춘다. 효과음은 별도로 조절한다. 음원 서비스나 새 외부 요청은 추가하지 않았다.

## 수정 및 빌드

이야기는 `scenario.json`, 순수한 분기·점수·엔딩 계산은 `source/story-rules.js`, 화면·투표·저장은 `source/game.js`에 있다. 승인된 시나리오는 이후에도 수정할 수 있다. 시나리오를 바꾸면 클라이언트와 서버 규칙을 함께 다시 만든다.

저장소 루트에서:

```text
python harm/harm_v3/source/build.py
python harm/harm_v3/source/build_rules.py
node harm/harm_v3/source/verify.cjs
node harm/harm_v3/source/verify-scenario.cjs
node harm/harm_v3/source/verify-experience.cjs
node harm/harm_v3/source/verify-browser.cjs
node harm/harm_v3/source/verify-scenario-browser.cjs
```

브라우저 검사는 Playwright와 Edge를 사용한다. 자산을 다시 패킹하려면 `sharp`, `@napi-rs/canvas`가 설치된 환경에서 `source/bake-assets.cjs`를 실행한다. 현재 자산을 쓸 때는 다시 패킹할 필요가 없다. 빌드에 API 키나 서비스 계정은 필요하지 않으며, 실시간 연결에는 기존 Firebase 공개용 설정만 사용한다.

`source/verify-classroom.cjs`는 실제 서버에 가상 교사·학생 계정과 방을 만들고 시험 후 정리한다. 실행 전 해당 서버에 테스트할 권한이 있어야 한다.
